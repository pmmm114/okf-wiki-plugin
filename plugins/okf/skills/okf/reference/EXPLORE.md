# 탐색 제공자 계약 (explore provider contract)

층간 승격 워크플로(Epic #197)가 소비하는 **탐색(신호·층 맵) 인터페이스의 정본**이다.
탐색 도구는 언제든 다른 것(외부 인덱서·검색 서비스 등)으로 교체될 수 있는 영역이므로,
워크플로는 특정 구현이 아니라 **이 계약에만 결합**한다 — study 디스패치가 계약(stdin
아이템·env var)만 정의하고 핸들러 실체를 소비처가 주입하는 것과 동형 원리다. 이 repo는
특정 외부 탐색 도구를 모른다(목적지 무참조의 계층 적용).

기본 제공자는 `scripts/core/okf_layers.py`다 — 같은 계약의 첫 구현체일 뿐 특권이 없다.
층 어휘·정초 순서는 `LAYERS.md`의 기계 판독 단일 원천을 따른다(여기 재기술하지 않는다).

## 1. 호출 규약

제공자는 실행 가능한 명령이며 두 연산을 구현한다. 응답은 stdout, 성공은 exit 0.

```
<provider> signals <bundle> [--json]
<provider> map <bundle> [--topic <프리픽스>] [--layer <층>] [--json]
```

- `--json`이면 아래 [응답 계약](#2-응답-계약)의 JSON을 낸다. 미지정 시 사람 가독
  렌더를 내도 되지만, 담는 데이터는 같은 계약 필드여야 한다.
- `--topic`은 주제(번들 내 디렉토리 프리픽스, 예: `produce` — 하위 디렉토리 포함),
  생략·`.`은 전체. `--layer`는 그 층의 개념만.

## 2. 응답 계약

필수 필드는 최소로, 확장은 관용으로 — 소비자는 모르는 필드를 무시하고, 선택 필드
결측을 우아하게 처리한다(스펙 §4.1 "미지 필드 거부 금지" 동형). `layer` 값은
LAYERS.md 어휘, 미분류는 `null`(개념 항목) 또는 `"(unclassified)"`(계수 키)다.

`signals` — 승격 신호 리포트("어디를 볼까"):

```json
{"topics": [{"topic": "<주제, 필수>",
             "counts": {"<층|(unclassified)>": 0},
             "ungrounded": ["<미접지 상위 개념 경로>"],
             "focus": [{"path": "<경로>", "refs": 0}]}]}
```

`map` — 주제 층 맵("거기에 뭐가 있나"):

```json
{"topic": "<주제>",
 "concepts": [{"path": "<경로, 필수>", "layer": null, "type": null,
               "description": null, "derived_from": ["<경로>"], "refs": null}],
 "edges_out": [{"from": "<경로>", "to": "<주제 밖 경로>"}]}
```

제공자 고유 확장(예: 관련도 점수)은 허용하되 **자문 표시 전용** — 소비자가 확장
필드에 로직을 걸면 유착이다.

## 3. 무유착 불변식

1. **탐색 출력은 게이트 입력이 아니다.** 승격 파이프라인(`okf_promote.py`)의 게이트·
   집행은 탐색 응답을 소비하지 않는다 — 재료 해시도 `snapshot`(결정적 계층)이 직접
   채집한다. 탐색이 누락·오탐해도 승격의 **정합성은 불변**이고, 탐색 품질은 판정
   **효율**에만 영향한다. 이것이 안전한 교체 가능성의 근거다.
2. **소비자는 계약 필드만 소비한다.** 제공자 내부 형식·점수·구현에 의존 금지.
3. **제공자는 번들을 읽기만 한다**(read-only). 번들 변경은 승격 파이프라인의 독점
   권한이다.
4. **원문 확인은 계약 밖이다.** 모델의 재료 원문 읽기(LAYERS §8 판정)는 제공자를
   거치지 않는 불변 권한 — 탐색은 후보를 좁힐 뿐, 판정 근거는 항상 원문이다.

## 4. 검증과 교체

- **계약 검증기** — 소비 측이 제공자 응답을 `okf_layers.validate_signals_payload` ·
  `validate_map_payload`(필수 필드·타입 검사, 미지 필드 관용)에 통과시켜 잘못된
  출력이 판정에 조용히 스며들지 않게 한다(fail-visible). 검증기는 소비 측 소유다 —
  제공자가 아니라 이 계약이 정본.
- **교체 주입(예약)** — `.okf-wiki.json`의 `explore.provider` 키로 외부 제공자 명령을
  지정한다(미설정 = 내장). 외부 명령 실행은 로컬 trust 승인이 필요하다(핸들러 trust와
  동일 원리). 배선은 후속 유닛(#204) — 그 전에도 이 계약이 확정돼 있으므로 교체
  가능성은 구조로 보장된다.
